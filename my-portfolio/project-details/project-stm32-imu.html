STM32 IMU Firmware

Firmware project centered on SPI communication, driver integration, interrupt-driven data capture, and live UART monitoring for an ISM330DHCX IMU.

  • STM32
  • C
  • SPI
  • UART
  • EXTI/NVIC

What I built

  • Implemented SPI communication on STM32 for reliable register-level control and sensor data acquisition.
  • Designed a hardware abstraction layer using stmdev_ctx_t to separate platform communication from sensor logic.
  • Debugged bring-up issues involving chip-select routing, SPI mode, data width, and clock configuration.
  • Implemented interrupt-driven acquisition with EXTI and NVIC to eliminate polling for data-ready signals.
  • Built a real-time UART pipeline for live 3-axis acceleration monitoring and validation.

What I learned

  • How low-level firmware debugging usually involves both code and hardware assumptions being wrong at the same time.
  • How register-level drivers can be structured cleanly without relying entirely on board support packages.
  • Why interrupt-driven design matters for responsiveness and efficiency in embedded systems.

Why it matters

This is the project that best captures my interest in firmware work. It forced me to deal with hardware behavior, driver structure, and real debugging rather than only writing application logic.
